# 命令与权限总表

> **本文档的用途**：集中记录当前**全部**命令、别名、可见范围、冷却/配额与投递渠道，作为对外说明与验收清单的唯一出处。
> **什么时候需要更新它**：新增/删除/改名任何命令、调整权限判定、调整冷却或配额、改变投递渠道（群 / 私聊 / 临时会话）时。

## 1. 通用约定

| 约定 | 说明 |
|---|---|
| 触发方式 | 群内需要 **@机器人** 才会响应（`!recalled` 是唯一例外）；私聊/群临时会话里直接发命令，不需要 @ |
| 群白名单 | 不在 `ALLOWED_GROUP_IDS` 的群不归档、不响应任何命令 |
| 未知指令静默 | 只 @ 机器人、闲聊、错别字、已删除的旧命令、形态不对的命令**一律不回复**，也不消耗冷却 |
| **回复文本里不出现任何群号** | 需要写群号的地方统一用 `<群号>` 占位符。白名单群号不列举、`status` 报告逐群数据只按「本群 / 其他群 N」汇总。群号只存在于 `.env`、SQLite 与日志中 |
| 权限分层 | **主人**（`AUTHORIZED_USERS`，超级管理员）> **群管理员**（该群 `GROUP_AUTHORIZED_USERS`）> **全体群成员** |
| 通配符 | 授权列表写 `*` 表示"该群全体成员"；`*` **不**能证明某人是**别的**群的成员，跨群操作时不算数 |

> **关于 @：** 手打的 `@可莉` 是普通文本、不会生成 at 段；机器人现在也认这种写法（2026-10-18 起），前提是去掉名字后紧跟的是已知命令。所以「@可莉 漂流瓶」和「@可莉 今天吃什么」都不会被误当成命令。

## 3. 逐条说明

### 3.1 漂流瓶（原「群精华」）

- 混合池 = **精华消息**（OneBot `get_essence_msg_list`）+ **群相册内容**（NapCat `get_qun_album_list` / `get_group_album_media_list`，遍历该群所有相册）。
- 类别决定优先级：显式 `相册` → 相册被配置关闭则只抽精华 → **连续同类补偿** → 按 `BOTTLE_ALBUM_SHARE`（默认 50）随机。
- 次数与冷却两个形式**共用**：它还是一个漂流瓶。冷却期间不扣次数，**每个冷却周期只提示一次**"还要等 N 秒"，之后静默；当天次数用满同样只提示一次。
- 同一内容当天不重复；当天全部捞过一遍后提示"明天再来"并**退还次数**。
- **近期防重复**：候选按「最久没被抽到」优先排序——每次从随机的 `BOTTLE_REPEAT_PICK_K`（默认 5）个候选里挑最近一次被抽到时间最早的那个，从未抽过的视为最旧、优先铺开。这是**排序而不是禁抽**：没有"X 天内不许出现"的硬窗口，池子里每条内容任何时候都可能被抽到；"多久才重复"是结果，由池子大小与每日抽取量决定（约 = 池子大小 / 每日次数）。`BOTTLE_REPEAT_MODE=off` 可一键回到纯随机。
- 图片取不回、或相册照片下载失败的对象会被跳过并记住，不再重试；只剩坏图时提示并退还次数。
- 抽到的如果是**视频**，直接转发视频，不下载也不做卡片。
- 卡片只在**真正发出后**才计入"已捞走"，发送失败可重试。
- 每种内容都会标出**被捞到的次数**：卡片副标题写「已被捞 N 次」，紧随其后的文字提示写「近 7 天里，这条内容被捞到过 N 次（含这次）」。
  - `N` = `essence_draws` 里该内容的行数。因为主键含 `day` 且当天已抽过的会被过滤，**同一内容每天最多被捞一次**，所以它等于"被捞到过多少天"；
  - `essence_draws` 只保留 `ESSENCE_DRAW_RETENTION_DAYS`（7）天，超期行会被清理，所以文案一律写「近 7 天」，不谎称历史总数。
- **「被抽到榜」已开放**：`被抽到榜` / `抽到榜` / `被捞榜`，返回**图片**（TOP10 内容被捞到的次数），见 3.5。

### 3.2 `漂流瓶 相册`（纯相册形式）

- **只从群相册随机**：不参与连续同类补偿、不看 `BOTTLE_ALBUM_SHARE`、**不回退到精华**。
- 失败会说明具体原因并退还次数，不会拿精华顶包：相册为空 / 照片全打不开 / 相册被配置关闭 / 今天相册已捞完。
- **配置优先**：`BOTTLE_ALBUM_ENABLED=0` 或 `BOTTLE_ALBUM_SHARE=0` 时只回"群相册这一半被关掉了"。
- 没有对称的"只要精华"形式：`漂流瓶 精华` **不是**可识别命令，按未知指令静默。

### 3.3 连续同类补偿

最近 `BOTTLE_SWITCH_STREAK`（默认 3）次**成功捞取**都是同一类时，下一次**强制先试另一类**。连续记录直接读 `essence_draws`（按 `drawn_at` 倒序），所以跨重启依然成立；阈值设 0 即关闭。补偿只调整优先级，首选那类为空时仍回退，不会空手而归。纯相册形式不参与补偿。

### 3.4 丢漂流瓶榜

| 分段 | 统计口径 |
|---|---|
| 【被丢进瓶子里最多的人】（Top10） | 内容被装进瓶子最多：对精华是**原消息作者**，对相册是**上传者** |
| 【最爱丢漂流瓶的人】（Top5） | **设精华次数 + 群相册上传数合并计算**——两种动作都是往池子里放东西 |

认不出上传者的相册内容只计入总数、不进个人榜，并在末尾单独说明。只统计当前仍在精华列表与群相册里的内容。

### 3.5 被抽到榜（TOP10，返回图片）

和 3.4 不是一回事：3.4 数的是**人**（谁丢/谁被丢），这里数的是**内容**（哪条被捞到的次数最多）。

- 命令：`被抽到榜`，别名 `抽到榜`、`被捞榜`。全体群成员可用，走非管理员 @ 冷却。
- 统计口径：`essence_draws` 里按内容的行数倒序；同次数时**最近被捞到的在前**。取前 10 条。
- **每行显示的是漂流瓶里的实际内容**（不是编号）：先按「群 + 相册」各拉一次现行池子，
  把榜单的键对应回具体消息 / 相册照片，然后渲染——
  - 标题行：发送者昵称（精华）或上传者（相册）；
  - 副标题：来源（`精华 · 由 XX 设为精华` / `群相册《相册名》`）+ `上次被捞到 MM-DD HH:MM`；
  - 气泡：精华消息的正文（最多 120 字，超出以「…」截断）；
  - 图片：**最多前 3 条**各带 1 张缩略图（240–260px），同一消息有多图时标注「另有 N 张图片」；
  - 右侧：`第 N 名 · M 次`。
- **原内容可能已经不在了**（移出精华列表、相册照片被删）。这时该行显示抽取时落库的 `label`
  （早期记录没有 label，则回退成「精华消息 #<消息号>」），并注明「原消息已不在精华列表里」/
  「原照片已不在群相册里」，不会假装还在。
- 图片只下前 3 条、只取每条的**第一张**：每条都是一次网络往返与一次缓存写入，10 条全下会让
  命令明显变慢；缩略图也单独收小（`LEADERBOARD_THUMB_SIZE=260`），否则一行就占半屏。
- **次数受 `BOTTLE_HISTORY_DAYS`（默认 30）限制**，卡片副标题会写明「近 N 天」，不谎称历史总数。另外同一内容每天最多被捞一次（当天去重），所以次数实际等于"被捞到过多少天"。
- 没有任何记录时回一句文字提示，不发空图。
- 名次画在**右侧**而不是标题里：标题若以「10.」开头，头像圆圈取首字符会显示成「1」，看着像第 1 名。
- 发送失败走 `safe_` 包装：记日志 + 回一句兜底提示，不会把异常抛进处理器。

### 3.6 撤回记录与全群冷却

- 默认只看最近 `RECALL_WINDOW_MINUTES`（默认 30）分钟内的撤回；更早的未召回记录只有主人能用 `撤回记录 全部` 翻出来。
- **全群共用一个 120s 窗口**（`group_cooldowns` 表）：一个群每 120 秒只能翻一次，谁先问谁得到，其余人被挡。被挡的**第一次**会收到"还要等 N 秒"，同一窗口内之后一律静默。**主人不受此限制**；窗口按群计，不跨群。
- 被**权限拒绝**的尝试（普通成员用 `私聊`、非主人用 `全部`）在冷却之前返回，**不占用**窗口。
- 记录的"是否已召回"按单条撤回事件记录（`recall_events.summoned_at`）：只有真正画进卡片的才算看过，被时间窗或条数上限挡下的保持未召回。发送失败不标记。
- `!recalled` 与 `撤回记录` 共用同一个全群窗口；它是唯一不需要 @ 的群内命令，且要求消息**只含文本**并精确等于 `!recalled`（带前后缀、空格或其他内容均不触发）。

### 3.7 私聊投递开关

| 位置 | 允许的操作 |
|---|---|
| 私聊（主人） | 开、关、查询状态 |
| 私聊（其他管理员） | 关、查询状态（**不能开**） |
| 群里（群管理员） | **关**、查询状态（**不能开**） |
| 群里（非管理员） | 收到管理员专属说明 |

关闭后的效果：群里 `撤回记录 私聊` 被拒绝且**不回落进群**（回落等于把要藏的内容公开），记录保持未召回；私聊入口的 `撤回记录` / `clear` 只回一句提示、不投递。**`私聊投递 开` 与 `help` 不被开关拦截**，所以关闭它不会把主人锁在外面。开关只影响私聊链路，群内普通 `撤回记录` 照常工作。

### 3.8 `clear`

只有主人能用（它会一次抹掉整群的待召回队列）。它把该群尚未召回的记录标记为已看过并删除这些记录关联的图片缓存，**不删除**普通聊天归档。普通成员与群管理员都会收到权限说明。

### 3.9 `status`

只有 `STATUS_USERS`（默认 `100000009`）能用，其他人发这句完全静默、也不计入冷却。报告含进程/内存/版本、OneBot 连接、归档量、未召回数、漂流瓶缓存与今日抽签、昨日总结状态、数据库与磁盘路径。**只发到主人的私聊，群里完全静默**；私聊发送失败时才回群里一句兜底提示。被 `STATUS_EXCLUDED_GROUP_IDS` 点名的群既不计入报告，在这些群里发 `status` 也完全静默。

### 3.10 `help`

群里按身份分块输出：`【大家都能用】` 与（管理员可见的）`【管理员】`。**不再包含【超级管理员】段落**——`撤回记录 全部` 与 `clear` 不打算在群里公开，因此群内 `help`、根 README 与本文档的命令总表都**不会**把它们列进群内可见清单；需要时用私聊 `help` 查看（那里会向主人列出）。被 `BOTTLE_ONLY_HELP_GROUP_IDS` 点名的群例外：`help` 只返回漂流瓶的用法，不出现撤回记录、昨日总结或任何管理员说明。

### 3.11 语音点歌 `炸乌云`

- 命令：`炸乌云` → 发默认那首（文件名含「让风告诉你」的）；`炸乌云 <歌名>` → 按名字片段点歌。
- **曲库是目录，不是代码**：`data/voice/` 下的音频文件就是曲库，歌名 = 文件名（不含扩展名）。
  加新歌只需把文件丢进去，**不用改代码、不用重启**（每次调用现读目录）。
  支持 `.mp3` `.silk` `.amr` `.wav` `.m4a` `.ogg` `.flac`。
- **以语音（OneBot `record` 段）发送**，不是文件、不是图片。
- **超过 `VOICE_MAX_SECONDS`（默认 60 秒）的歌会被自动截成前 N 秒再发**：
  在 **MP3 帧边界上切**（不重新编码、无损、不会切出半帧爆音），实测把 3:47 的歌
  （9,455 帧 / 226.9 秒）截到正好 60.00 秒，耗时约 44 ms。
  - `.mp3` / `.wav` / `.amr` 支持截断；`.silk` / `.flac` / `.m4a` / `.ogg` 截不了，
    会原样发送（交给 NapCat，失败时有兜底文案）。
  - 截断结果缓存到 `data/voice/.trimmed/`，文件名带源文件的 mtime 与大小——**换了素材
    自动失效**；第二次调用命中缓存（实测 0.5 ms）。
  - 原本就不超长的歌**不会被复制**，直接发原文件。
- **发给 NapCat 的文件必须是 `file://` URI 或绝对路径**（2026-10-17 实测）：相对路径会被
  拒成 `retcode 1200 · 文件处理失败: 识别URL失败`。代码里先试 URI、失败再回退绝对路径，
  日志会写明用的是哪种（实测一直是 `uri form`）。截断副本用纯 ASCII 文件名，避免中文路径
  再引入变量。
- 剩下一条现实限制（NapCat / QQ 侧，代码绕不过）：能不能解码取决于 NapCat 对容器的支持，
  `.mp3` / `.silk` / `.amr` 最稳。发送失败时**不静默**：回一句说明，同时把异常写进日志。
- 找不到歌 / 曲库为空时给的是**可操作的提示**（告诉你该把文件放到哪个目录），不是干巴巴的报错。
- 曲库里有多首时，"炸乌云"固定放默认那首（**不随机**），避免"每次炸乌云放的都不一样"。

### 3.12 喝水提醒（私聊开关）

按固定作息每天提醒 **19 次**，**私聊主人 + 群里各发一份**：

| 时间 | 类型 |
|---|---|
| 07:50 | 起床（专属文案） |
| 08:30 / 09:05 / 10:00 / 10:30 / 10:50 | 上午喝水 |
| 12:40 | 午餐后 |
| 13:50 | 午休起来 |
| 14:00 / 14:45 / 15:30 / 16:15 / 17:00 / 17:45 | 下午每 45 分钟（18:00 下课不提醒） |
| 19:00 | 晚餐后 |
| 20:00 / 21:00 / 22:00 / 22:30 | 每小时，最后一杯 |

- 开关：**主人私聊** `喝水提醒`（看状态）、`喝水提醒 开`、`喝水提醒 关`；
  `喝水提醒 测试`（也认 `试一下` / `test`）会**立刻**发一条带【测试】前缀的提醒，
  用于验证通道——**关着也能测**。状态存 `bot_settings`，
  重启后保留，默认开启；非主人只会收到"只有主人能开关"。
- 分群排除：`WATER_EXCLUDED_GROUP_IDS` 里的群收不到群提醒（私聊提醒不受影响）；
  `喝水提醒 测试` 同样不会发到这些群。
- 实现：`runtime/water.py`，20 秒 tick 的 asyncio 循环按 `HH:MM` 匹配，同一分钟只触发一次，
  不依赖 apscheduler。

## 4. 私聊 / 群临时会话入口

只服务撤回记录相关的工具（`撤回记录`、`clear`、`help`、`私聊投递`），其他内容（含好友闲聊）完全静默。

能进入的条件是**被 QQ 号点名**（全局 `AUTHORIZED_USERS` 或某个群的 `GROUP_AUTHORIZED_USERS`），或者**由该群的群临时会话发来**且该群配置为 `*`（临时会话本身证明了这个人在群里）。私聊侧**始终是管理员工具**：普通成员即使在私聊里也拿不到记录。

"查哪个群"的来源顺序：命令里显式的群号 → 群临时会话事件上的来源群 → 只有一个白名单群时的那个群；都确定不了时回一句提示要求补群号。私聊不受全群 120s 冷却限制。

## 5. 已删除的旧指令

改版前的 `精华`、`抽精华`、`来一条精华`、`群精华`、`精华榜`、`群精华榜`、`精华排行` **已从命令集移除**，不再被识别：群里打这些词会走"未知指令 → 完全静默"，不回复也不消耗冷却。命令集定义在 `plugins/group_bot/handlers.py` 的 `BOTTLE_COMMANDS` / `BOTTLE_RANK_COMMANDS`。
