## 2. 文档约定

### 2.1 状态型文档（stateful docs）

**约定：下列文档描述「当前实际行为」，改动功能时必须同步更新对应文档。**

- 状态型：`architecture.md`、`commands.md`、`configuration.md`、`operations.md`。
- 判断标准很简单：**读它的人会拿它当"现在就是这样"来用**，那它就是状态型。
- 状态型文档里不要写「曾经/将要」，除非那个「曾经」本身对理解现状必要；
  历史一律交给 CHANGELOG。
- 改功能的提交里，**代码与文档同一次提交**。文档漏更新等于留下错误描述。

### 2.2 CHANGELOG 只追加

`CHANGELOG.md` 记录历史，**不改写既有条目**：迭代号只增、不重排、不回填修改。
发现旧条目写错时，在新的迭代里写一条修正说明，而不是改历史。
（迭代 1–8 是 2026-10-14 从 `git log` 回填的，文件里已单独说明。）

### 2.3 决策与理由进 decisions

「做了什么」写进 CHANGELOG；**「为什么这样做」写进 `decisions.md`**（见 1.2，待新建）。
理由是易失信息：代码只体现结果，几个月后没人能从代码里读回当时的取舍与代价。

### 2.4 文件名与语言

- 正文与标题用简体中文。
- 对照信息优先用 Markdown 表格。
- 新文档用英文小写文件名（`development.md`、`operations.md`）；既有中文文件名暂不改名，
  以免打断已有链接与引用。**要改名就一次性改完并更新所有引用。**

### 2.5 根 README 的边界

根 [README.md](../README.md) 只保留三件事：项目是什么、快速开始、指向本目录的导航表。
**不要**把逐条命令说明、模块清单、表结构、配置项清单、运维细节写回根 README——
它们分别属于 `commands.md`、`architecture.md`、`architecture.md`、`configuration.md`、
`operations.md`。
